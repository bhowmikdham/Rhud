## 0. Verification corrections — read before building
An adversarial pass checked the spec against the live `apps/api` + component code. Verdict: **fix-first**. The design is sound; these corrections override the spec body where they conflict:

**Do NOT 'fix' the VP-at-CEO-gate button.** The spec (§4, §9-Q6) claims a VP sees a final-approve button that throws a server guard at `pending_ceo_approval`, and that the redesign render-gates it off. That bug does not exist — `final-approval-card.tsx:43` already gates `canAct = admin || ceo || (vp && level==='vp')`, so a VP already sees a read-only "only CEO can act" state. Keep that behaviour; treat §9-Q6 as already-answered. Do not rewrite this code.

**`escalated` is not rep-resolvable.** The spec's hold overlay lists "Revise & resubmit" as the `sales_employee` CTA, but only `returned_to_sales` / `awaiting_clarification` auto-clear on client resubmit. At `escalated` the resolver is sales_manager / admin / ceo. A `sales_employee` viewing `escalated` must see **"Waiting on manager decision"**, not a resubmit CTA.

**Delivered CTA is inert until backend lands.** `closed` and `expired` have **zero status writers** in `apps/api`. `DealOutcomeCard`'s "Mark won/closed" can only fire the existing Odoo drawer actions today; persisting `status='closed'` (and any `expired` sweep) needs a **new API endpoint** (§9-Q1/Q2). Ship the card wired to Odoo only and treat `closed` as display-only, or schedule the backend work first.

**`draft_ready` send action lives elsewhere.** The spec attributes "Send / Mark sent" to this page's Proposal-stage primary, but those actions live in the untouched `/proposal` subroute. The detail page's Proposal primary should *link into* the workspace, not imply it sends from here.

**These two are real bugs the redesign must actually fix (not regress):**
- `ReviewerHoldActions` empty-box: `page.tsx:534` renders the "Need to pause before approving?" bordered container for **all** roles while `canAct` only gates the inner buttons (`reviewer-panels.tsx:552`) — non-reviewers see an empty box. Lift `canAct` to the wrapper.
- Poll re-subscription: `SiteScopeCard` (3s) and `ExtractedPointsCard` (5s) re-subscribe their intervals on every tick; Phase E must gate polls on `open && inFlight` with stable deps. Note the regression risk: a live crawl goes invisible once its section collapses off the Pricing stage (§9-Q5) — decide whether an in-flight crawl keeps polling regardless of stage.

**Highest blast-radius step:** Phase C (splitting `ApprovalCard` @737 into `PriceSummary` + `ApprovalActions` + `TechAdjustPanel`). The `techAdjustedFresh` binding (@778), `decisionMade` post-approval states (@783/@488), the offers/tier math (@798–835), and tech_team-only `TechAdjustPanel` must survive across the full status×role matrix. Gate it behind that test matrix.

## 1. The redesign in one screen

### Mental model — "One screen, one job; the rest in sections I open when I want them."

You land on an opportunity. The page reads **your role** and the **deal's lifecycle stage** and gives you, above the fold, exactly one thing: a **Stage Header** that shows where the deal is on a 5-station track, a one-line *what-happens-next*, an explicit **"Your turn" / "Waiting on {actor}"** badge, and the single **primary action zone** that is actually yours. Below it sits a thin **context strip** (lead health one-liner + classification/reviewer/links/odoo chips, each opening a drawer) and then a short stack of **labelled accordion sections, collapsed by default**, every header carrying a **live count/state badge** so you never miss activity in a section you haven't opened. You never scroll past another role's task to find yours; the page never fetches or polls for a panel you haven't expanded.

The model the user keeps is a vertical sentence: **Stage → my one move → (optionally) drill in.**

## 2. Stage-driven behaviour

One new pure selector, `stageOf(status)`, maps the 17 statuses to 5 forward stations + 2 side-states. It drives the Stage Header (label, stepper position, tone) and the `STAGE_PRIMARY` slot. **`predicted` and `pending_approval` collapse into one Approval-input stage** (the phantom-forward-state constraint — approve/reject keep acting on the latest prediction regardless of which of the two it's in, so admin `revert-approval` keeps working).

```
stageOf(status):
  issued, in_progress                                   → 'discovery'
  submitted, predicted, pending_approval                → 'pricing'      (submitted=pre-prediction, predicted/pending_approval=approve-input)
  pending_vp_approval, pending_ceo_approval             → 'approval'      (final gate)
  approved, drafting, draft_ready                       → 'proposal'
  sent, closed                                          → 'delivered'
  returned_to_sales, awaiting_clarification, escalated  → side:'hold'     (transient overlay; tone=warn)
  rejected                                              → side:'rejected' (terminal; tone=danger)
  expired                                               → side:'expired'  (see §9 Q4 — currently unreachable)
```

| Stage (stations) | Page leads with (PRIMARY) | Primary CTA | Who acts | Open-by-default section |
|---|---|---|---|---|
| **Discovery** (`issued`, `in_progress`) | `ScopingQuestionsCard` / `GatheringLinkCard` (B11) — issue / copy / re-issue link, expiry + access count | **Send scoping link** (or **Re-issue**) | sales_employee / sales_manager / admin (client acts off-platform) | none (only primary + facts summary) |
| **Pricing** (`submitted`, `predicted`, `pending_approval`) | If `prediction` → `PriceSummary` hero. `submitted` & `!prediction && quote` → `NoPredictionCta` (B7). `!prediction && !quote` → "No rate card" warn (B8). | **Approve at a tier** (manager/admin) · **Run prediction** (rep, at `submitted`) · **Lodge tech price** (tech) | sales_manager / admin approve; tech adjusts; sales_employee runs predict | **Scope evidence** (B12) — the one stage where a live crawl is load-bearing |
| **Approval** (`pending_vp_approval`, `pending_ceo_approval`) | `FinalApprovalCard` (B3) for the gate-owning role; compact "Awaiting {VP/CEO} sign-off" for everyone else | **Final-approve / Final-reject** | vp_sales (VP gate), ceo (both gates), admin (both) | none (Pricing detail collapsed) |
| **Proposal** (`approved`, `drafting`, `draft_ready`) | `ProposalSummaryCard` (B17) — status chip + CTA into proposal workspace | At `draft_ready`: **Send to client / Mark as sent**; `drafting`: wait (polls in workspace) | sales_employee / sales_manager / admin | **Justification & rationale** (B16) — wanted while sending |
| **Delivered** (`sent`, `closed`) | `DealOutcomeCard` (**NEW**) — Mark won / Mark lost / Reopen | **Mark won / Mark lost** | sales_employee / sales_manager / admin | none |
| **side: Hold** (`returned_to_sales`, `awaiting_clarification`, `escalated`) | **Takes over the screen.** Hold banner (B5, warn tone) + `ReviewerHoldActions` (B6) + the relevant edit inline (`AssumptionsExclusionsCard` for `returned_to_sales`, the question for `awaiting_clarification`) | **Revise & resubmit** (rep) / reviewer re-acts | sales_employee revises; reviewers re-act | all reference force-collapsed |

**Hold is an overlay, not a dead-end stage** (ground-truth constraint): client resubmit writes `submitted` unconditionally, auto-clearing the hold → page returns to Pricing. The Stage Header keeps the *underlying* station highlighted and caps it with a warn band, so resolving the hold visibly returns you to the track.

## 4. Per-role view

The Stage Header's **"Your turn" / "Waiting on {actor}"** badge is driven by a `status→actor` table (below), **never by button-absence**. Role gating moves **up to the mount/region level by `(stage, role)`** — an inert panel never occupies space *or fires network* for someone who can't use it.

```
ACTOR_BY_STATUS:  issued/in_progress → client · submitted → sales (predict)
  predicted/pending_approval → sales_manager · pending_vp_approval → vp_sales
  pending_ceo_approval → ceo · approved/drafting → system · draft_ready/sent → sales
  holds → sales (returned)/reviewer · rejected → admin (revert)
```

| Role | Pricing/Approval PRIMARY | Their CTA | Gating notes |
|---|---|---|---|
| **sales_employee** | `PriceSummary` read-only + **"Waiting on: {reviewer} for approval."** No tier grid, no hold box. | `submitted`: **Run prediction**. `draft_ready`: **Send / Mark sent**. `predicted`: explicit "no action needed." | Never mounts `ApprovalActions`, reviewer-notes-edit, line-item-edit, or `ReviewerHoldActions`. Kills the "big card, no button" dead-end. |
| **sales_manager** | `PriceSummary` + full **`ApprovalActions`** (base/recommended/aggressive/tech tiers, custom override, reject) + `ReviewerHoldActions`, one cluster. | **Approve at a tier** / send-back / clarify / escalate / reject. | Decision + supporting edits (notes, line items) surface together, not scattered. Cannot final-approve gates or revert. |
| **tech_team** | `PriceSummary` (read-only) with **`TechAdjustPanel` promoted as the primary input**; tier grid collapsed into a "model recommendation" `<details>`. | **Lodge adjusted price + note** (bound to current `prediction.id` — preserve `techAdjustedFresh` @778). | Re-predict and Approve/Reject stay hidden (already are). Hold actions available. |
| **admin** | Superset: `ApprovalActions` + `TechAdjustPanel` + **Revert** + (at gates) `FinalApprovalCard`. | Everything — universal escape hatch. | Sees/expands all sections. Only role that reaches `pending_approval` via revert. |
| **vp_sales** | Pre-gate: **"Waiting on: manager review — you'll sign off if it crosses the VP threshold."** At `pending_vp_approval`: `FinalApprovalCard` primary. | **Final-approve / Final-reject** (VP gate). | At `pending_ceo_approval` the button is **render-gated OFF** (not just server-blocked) → "Awaiting CEO sign-off." Kills the throwing-button bug. |
| **ceo** | "Waiting on manager review" until a gate; at either gate `FinalApprovalCard` primary. | **Final-approve / Final-reject** at both gates. | Outranks VP. |
